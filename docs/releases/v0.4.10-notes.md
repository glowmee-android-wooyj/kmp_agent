# v0.4.10 — 원본 승인과 구현 진행 분리

v0.4.9 이후 PR #31을 포함한 패치 릴리스입니다. 승인된 범위 안에서 코드를 수정할 때 원본·기술 승인이 매번 무효화되던 문제를 해결하고, 기존 v1 승인 근거를 보존한 채 같은 실행을 이어갈 수 있게 합니다. 최종 SHA·원격 검증 결과는 게시 본문에서 확정합니다.

## v0.4.9 대비 수정

- `requirement_lineage`에 한해 구현 진행 digest와 동결 원본 권한을 구분합니다. 기존 계약·native 응답·개설 코드 스냅샷·checkpoint·receipt·대체 이력을 바꾸지 않습니다.
- 입력·기술 artifact·subject·task 소유·허용 코드 범위와 capture 실패 검사는 유지합니다. 다른 typed purpose는 정확한 코드 상태 비교를 계속 사용합니다.
- 기존 `recover-question`·`resume`을 재사용합니다. 같은 활성 시도를 유지하며 승인 복제나 시도 예산 초기화를 요구하지 않습니다.
- 운영 지침의 상위 안내를 목적별 승인 기준과 일치하도록 정비했습니다.

명령은 수동 호출하고 내부에서 현재성을 검사합니다. 원본 승인은 코드 검토·제품 인수를 대신하지 않으며 실제 입력·범위 변경은 새 승인이 필요합니다.

## 설치·업데이트

신규 설치는 게시된 v0.4.10 bootstrap을 명시 선택합니다. 임시 경로와 제품 Git 루트는 실제 사용할 경로로 바꾸세요.

```sh
rtk proxy git clone --depth 1 --branch v0.4.10 git@github.com:wooyj-1217/kmp_agent.git /tmp/kmp-agent-bootstrap
rtk proxy python3 /tmp/kmp-agent-bootstrap/bootstrap.py install --source git@github.com:wooyj-1217/kmp_agent.git --ref v0.4.10 --target /path/to/product
```

v0.4.3~v0.4.9 설치본의 프로젝트 루트에서는 다음 단일 명령을 사용합니다.

```sh
rtk proxy python3 .kmp-agent/agent.py update --ref v0.4.10
```

기존 source를 사용하므로 다른 셸 명령·`--source`·`--target`을 덧붙이지 않습니다. v0.4.2 이하는 사용자 터미널의 새 bootstrap으로 전환합니다. 선택 SHA·runtime과 새 세션의 훅 신뢰·활성을 확인하세요. 기존 승인·checkpoint를 직접 편집하지 않습니다. 필요한 공식 재검증은 기존 원문으로 `recover-question`을 사용하고, 중단된 열린 실행은 같은 실행 ID의 `resume`으로 재개합니다. 제품 업데이트·승인 복구·재개는 별도이며 자동 수행되지 않습니다.

[0.4.10 설치 안내](https://github.com/wooyj-1217/kmp_agent/blob/v0.4.10/docs/installation.md)

## 검증 범위와 제한

동일 구현의 관련 회귀 **174개 PASS**, 강화된 핵심 **10개 PASS**, PR 제출 코드의 clean checkout 핵심·설치 CLI **11개 PASS**를 확인했습니다. v0.4.9의 합성 native fixture에서 두 번째 수정 차단을 재현하고 원본·범위 변경, 다른 purpose의 코드 변경, 변조된 native/checkpoint 거부와 정상 재개를 검증했습니다. 최종 후보·원격 태그의 신규 설치/업데이트·기존 승인 보존 결과는 게시 본문에서 확정합니다.

실제 인간 인증·제품 승인이나 인수를 합성 시험으로 대신하지 않습니다. 전체 테스트 신규 재실행·실제 설치본 Codex 훅·모델 E2E·공통 예제·실제 제품 업데이트/승인 복구/재개/인수는 NOT_RUN입니다. 개인 제품 자료·원본 로그는 공개하지 않습니다.
