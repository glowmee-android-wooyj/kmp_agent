# v0.4.11 지원 현황

VERSION **0.4.11**, 태그 **v0.4.11**의 제공 범위다. 직전 배포 [v0.4.10](v0.4.10.md)의 커밋은 `00ffa84a8d23c18bbe0a9855089b063073cc3151`이다. 이번 배포는 [PR #33](https://github.com/wooyj-1217/kmp_agent/pull/33)을 포함한다. 최종 SHA와 원격 검증 결과는 [GitHub Release](https://github.com/wooyj-1217/kmp_agent/releases/tag/v0.4.11)에서 확인한다.

## 중단 후 명령 실행 복구

- 작업을 재개한 뒤 상위 로그가 이미 닫혀 빌드·테스트에 `run already finished`가 나오면 [명령 로그 연결](../execution-policy.md#종료된-상위-실행-뒤-명령-로그-이어가기)로 같은 시도에 새 명령 로그를 연결한다. 원래 작업·승인·시도·종료 이벤트를 보존한다.
- 정상 반환한 단독 관리 명령은 소유권 해제와 하위 프로세스 종료를 확인한 뒤 같은 시도의 다음 명령에 실행 소유권을 넘긴다. 중단이나 소유권이 불확실한 경우 [실행 복구 절차](../recovery-contract.md)를 적용한다.

## 흐름별 지원과 제약

| 흐름 | 제공 범위와 조건 |
| --- | --- |
| 설치·init·update | 태그 또는 전체 SHA를 명시 선택한다. 설치본 훅 신뢰·활성은 새 Codex 세션에서 확인한다. |
| 기획 생성·검토 | 기존 단계·원본·native 승인 절차를 사용한다. |
| 디자인·시안·검토 | 기존 단계·시안·독립 검토 계약을 적용한다. |
| 개발 작업 생성·실행 | 활성 work 시도 및 승인된 범위·기술·명령을 검사한다. |
| 실패 반환·보완·재검증 | 기존 복구·resume과 종료된 상위 로그 이후의 명시적 명령 로그 연결을 지원한다. |
| 변경 감지·개발·재검증 | 명령 연결과 실행 시점에 현재 계약을 검사한다. |
| 산출물·실행·로그·사용량 | 수집 보고서가 이전·후속 명령을 원래 시도에 연결한다. |
| 개발 작업 병렬 실행 | 동시 실행 소유권을 검사하고 불확실한 자식 프로세스의 소유권 인계를 거부한다. |
| 하네스 결함·PR | 검토한 수정은 명시 승인으로 머지·배포한다. 제품 적용은 설치 프로젝트에서 확인한다. |

## 설치·전환과 검증

[설치 안내](../installation.md)의 v0.4.11 bootstrap을 선택한다. v0.4.3~v0.4.10 설치본은 프로젝트 루트에서 기존 설치 소스를 이용해 업데이트한다.

```sh
rtk proxy python3 .kmp-agent/agent.py update --ref v0.4.11
```

v0.4.2 이하는 사용자 터미널에서 새 bootstrap으로 전환한다. 업데이트 후 작업 상태에 맞게 [복구 절차](../interruption-recovery.md#작업은-재개됐지만-상위-명령-run이-종료된-경우)를 적용한다. 최종 검증 결과는 Release 본문에 기록한다. 실제 제품 KMP 빌드와 실제 Codex 훅 신뢰·활성 확인은 적용 프로젝트에서 수행한다.
