# v0.4.10 지원 현황

VERSION **0.4.10**, 태그 **v0.4.10**의 제공 범위다. 직전 실제 배포 [v0.4.9](v0.4.9.md), 커밋 `fac32431d8ee474a378fef26a8ac790f7778af65` 이후 [PR #31](https://github.com/wooyj-1217/kmp_agent/pull/31)을 포함한다. 준비 기준은 머지 커밋 `0a7d738a232d1c2d1b2f186aef63d491e3316b17`이며 최종 SHA·원격 태그 검증·게시 결과는 [GitHub Release](https://github.com/wooyj-1217/kmp_agent/releases/tag/v0.4.10)에서 확정한다.

## v0.4.9 이후 수정

추적된 구현 작업의 원본 승인이 첫 허용 코드 변경 뒤 무효화되어 다음 수정·명령·재개를 막던 결함을 수정한다. 정확히 `purpose='requirement_lineage'`의 현재성 비교에서만 `code_basis.state_sha256`를 제외해 동결 요구·기술·원본 소유 범위의 승인과 구현 진행을 구분한다.

- 기존 v1 계약·개설 코드 스냅샷·질문 suffix·checkpoint·native 응답·receipt digest·대체 이력을 바꾸지 않는다. 같은 유효 원문으로 소비·공식 복구 검증을 할 수 있으며 새 스키마나 승인 복제를 요구하지 않는다.
- 질문·subject·명시 artifact·실제 입력 bytes·task/feature/role·작업 범위·tracking 유무와 `scope`/`code_paths`/`scope_policy`는 계속 일치해야 한다. 명시 입력이나 artifact에 코드 파일을 포함했다면 그 bytes도 고정된다.
- 코드 capture와 symlink 등 실패 검사는 유지한다. 다른 typed purpose는 내용·모드·HEAD를 포함한 정확한 코드 상태 비교를 유지한다.
- 기존 `recover-question`·`resume`을 사용해 같은 활성 시도를 이어가며 시도 예산을 초기화하지 않는다. 입력·범위가 실제로 바뀌면 새 승인과 명시적인 대체 체인이 필요하다.

[승인 목적별 현재성](../approval-authority.md#원본-권한-승인과-구현-진행)과 [요구사항 계보](../requirement-lineage.md)를 따른다. 상위 [운영 안내](../operations.md#human-review)의 typed 승인 설명도 같은 목적별 기준으로 정비했다. 원본 승인은 코드 검토·QA 권한·제품 인수를 대신하지 않는다.

## 설치·전환

신규 설치는 [설치 안내](../installation.md)의 v0.4.10 bootstrap을 명시 선택한다. v0.4.3~v0.4.9 설치본은 프로젝트 루트에서 기존 source를 재사용하는 단일 명령을 사용한다.

```sh
rtk proxy python3 .kmp-agent/agent.py update --ref v0.4.10
```

다른 명령·`--source`·`--target`과 결합하지 않는다. v0.4.2 이하는 사용자 터미널의 새 bootstrap으로 전환한다. 선택 SHA·runtime과 새 세션의 훅 신뢰·활성을 확인한다. 기존 질문·승인·checkpoint를 편집하지 않는다. 유효한 ANSWERED 승인은 소비 시 재검사하며 공식 재검증이 필요하면 기존 원문의 locator/hash와 계약 digest로 `recover-question`을 사용한다. `BLOCKED`의 열린 실행은 유효한 checkpoint를 확인하고 같은 실행 ID의 `resume`으로 재개한다. 업데이트 자체는 제품 작업을 자동 재개하거나 과거 승인을 변경하지 않는다.

## 검증 범위

2026-11-18 PR #31의 동일 구현에서 승인·복구·텍스트 전송·계보·실행 정책·추적·기술 제약·제품 guard·단계 준비의 관련 **174개 PASS**, 자동 질문 checkpoint를 강화한 핵심 **10개 PASS**, 제출 커밋 `560e1703a51fdea25038d7a97b300dedc6cf9d98`의 clean checkout 핵심·설치 CLI **11개 PASS**를 확인했다. v0.4.9의 별도 checkout에서는 두 번째 패치 거부를 합성 native fixture로 재현했다. 최종 후보와 코드·테스트 내용 해시를 대조해 결과 적용성을 확인한다.

후보 신규 설치·init·재설치·v0.4.9→v0.4.10 update와 기존 v1 native 승인·checkpoint 보존 및 같은 시도 재개, 최종 원격 태그/SHA 검증 결과는 Release 게시 본문에서 확정한다. 개인 제품 자료·원본 로그는 공개하지 않는다. 합성 fixture는 실제 인간 인증·제품 인수를 뜻하지 않는다. 전체 테스트의 신규 재실행·실제 설치본 Codex 훅·모델 E2E·공통 예제·실제 제품 업데이트/승인 복구/재개/인수는 **NOT_RUN**이다.
